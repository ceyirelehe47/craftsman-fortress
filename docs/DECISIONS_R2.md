# R2 决策记录：可修改世界与存档底座

## R2-01 · 修改覆盖层而非全世界快照

Seed、世界尺寸和生成器修订决定基础世界。存档只记录最终值不同于基础世界的体素坐标与方块；恢复基础值时覆盖项自动删除。这样存档大小与玩家修改量相关，而不是与整张三维地图体积相关。

## R2-02 · 语义哈希

R1 的 `world_hash()` 继续用于验证 Chunk palette 与索引的确定性表示。R2 新增 `semantic_hash()`，按固定坐标顺序混合解码后的 BlockId，不受 palette 插入顺序影响。存档的基础哈希与最终哈希均使用语义哈希。

## R2-03 · 双槽原子协议

不依赖跨平台“覆盖式 rename”。逻辑路径轮换 `.slot0` / `.slot1`：写新状态时始终保留当前最新有效槽，目标槽先腾空，再由同目录临时文件原子重命名。加载分别校验两个槽并选择 generation 最大的有效槽。

## R2-04 · 安全编辑边界

- 基岩不可删除或替换；
- 玩家不可放置 Bedrock；
- `H-1` 顶层必须保持空气，以保留 R1.1 的相机恢复安全层；
- 本轮放置材料固定为 Stone；
- 不做背包、材料选择、挖掘耗时、工具耐久或建造规则。

## R2-05 · 启动加载而非运行时热重载

本轮通过 `--load PATH` 启动加载。F5 负责保存；不实现 F9 热重载，避免在 Mesh 全量替换期间向玩家展示新旧世界混合帧。后续需要热重载时，应增加专用加载状态与原子 Mesh 交换。

## R2-06 · 验收分层

`scripts/r2_acceptance.sh` 必须先完整重跑 R1 图形验收，再运行 R2 头部往返测试。实现方与隔离 Reviewer 均从全新克隆执行，用户不参与操作或判断。
