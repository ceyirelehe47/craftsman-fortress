# R5 模块化建筑构件层

## 分层

- `World` / Chunk / `BlockId`：1m 地形体素；
- `ObjectStore`：R4 独立静态对象；
- `BuildingStore`：R5 薄墙、楼板、门窗、楼梯、屋顶、柱梁；
- ECS Entity / Mesh / Material：可销毁并重建的视觉表现。

建筑构件不得写入地形 palette，也不得借用 ECS Entity 作为持久身份。

## 稳定构件类型

| 类型 ID | 槽位语义 | 当前尺寸/层高 |
|---|---|---|
| `floor_basic` | 水平单元平面 | 1×1m 薄楼板 |
| `wall_basic` | 规范化竖直边 | 1m 长、3m 高 |
| `doorway_basic` | 与墙相同的竖直边槽 | 1m 长、3m 高门洞 |
| `window_basic` | 与墙相同的竖直边槽 | 1m 长、3m 高窗构件 |
| `stair_basic` | 离散楼梯体积 | 1×3m，升高 3m |
| `roof_flat_basic` | 水平单元平面 | 1×1m 薄平屋顶 |
| `column_basic` | 网格点 | 3m 高 |
| `beam_basic` | 水平边 | 1m 长 |

已有稳定类型 ID 不得被重用于其它语义。

## 坐标与旋转

- 锚点全部为整数世界坐标；
- `yaw_quarters=0/1/2/3` 分别指向 `+X/+Z/-X/-Z`；
- 同一边的正向和反向描述规范化为同一占用槽；
- 任意浮点欧拉角、Mesh AABB 和渲染 Pivot 都不是玩法权威数据。

## 支撑规则

1. 地面楼板可以直接放在实体地形上方。
2. 抬高楼板和屋顶的四个角必须全部有结构端点。
3. 墙、门洞、窗和柱的底端必须由地形或楼板平台支撑。
4. 梁的两个端点必须分别由墙或柱顶端支撑。
5. 楼梯必须从一个楼板锚点连接到沿朝向 3m、向上 3m 的另一个楼板锚点。
6. 删除或移动支撑件后若剩余集合不合法，操作整体失败且无副作用。

## 冲突规则

- 墙、门洞、窗共享一种边槽，单条边只能存在其中一个；
- 同一位置不能同时存在楼板和屋顶；
- 同一点只能存在一根柱；同一水平边只能存在一根梁；
- 楼梯体积不能穿过其它建筑、实体地形或独立对象；
- 建筑薄面不能切入独立对象逻辑体积；
- 地形编辑不能破坏任意建筑支撑或占用空间。

## 运行时操作

- `F1/F2/F3/F4/F6/F7/F8/F9`：选择楼板、墙、门洞、窗、楼梯、屋顶、柱、梁；
- `H`：旋转 90°；
- `J`：放置，或提交移动；
- `K`：选择光标下最近且未被地形/对象遮挡的建筑；
- `L`：进入移动模式；
- `Backspace`：删除所选构件；
- `PageUp/PageDown`：以 3m 为单位调整放置层；
- `Esc`：取消移动；
- `F5`：保存地形、对象和建筑三层状态。

## 当前边界

R5 只建立模块化静态构件和确定性结构关系。门洞尚不驱动门的开关状态，窗没有破损状态，楼梯尚未注册导航连接，抬高楼板尚未成为 R4 对象的支撑来源。
