# 决策记录（Agent 自主决定项）

任务书第 9 节授权范围内的全部自主决策及理由。编号延续 V0.1 的 D-01..D-06（见 git 历史），
本轮 V0.2 从 D-07 起记。

## D-07 · Bevy 补丁版本与工具链（2026-09-13）

- **决定**：`bevy = "=0.19.1"`（精确锁死），`Cargo.lock` 一并提交；工具链 rustc **1.98.1**。
- **理由**：任务书冻结 0.19 系列。0.19.1 是当前最新补丁版。Bevy 0.19.1 的 MSRV 为 1.95.0、
  edition 2024，仓库原 1.86.0 工具链无法编译；选择 1.98.1（当前 stable，2026-09-01 发布），
  在 `rust-toolchain.toml` 锁定以保证可复现。0.19 系列内的后续补丁升级将作为独立依赖变更处理。

## D-08 · 升级策略：迁移而非重写（2026-09-13）

- **决定**：保留 V0.1 的模块划分与全部实现，按编译器/迁移指南逐点迁移到 0.19 API。
- **理由**：任务书 4.1 要求"保留可用实现，不无依据重写"。实际迁移共触碰 7 类 API
  （Trigger→On、EventWriter→MessageWriter、FontSize::Px、WindowResolution::new(u32)、
  gizmos.cube、shadow_maps_enabled、Assets::insert 返回值）+ 系统排序改为 SystemSet，
  均为局部改动，验证了原架构与 Bevy 解耦良好。

## D-09 · 升级中发现并修复的 V0.1 缺陷（2026-09-13）

升级使 V0.1 测试首次真正编译运行，暴露以下被掩盖的缺陷，全部修复：

1. **渲染顶点色格式**：`ATTRIBUTE_COLOR` 写入 `[f32;3]` 在 0.19 直接 panic（Float32x4 要求）。
   V0.1 无任何证据包留存与此吻合——渲染路径从未跑通。改为 RGBA(alpha=1.0)。
2. **`World::set_voxel` 返回值 bug**：文档承诺返回旧值，实现返回新值。已修。
3. **洞口探测恒失效**：探测检查 `voxel(x, column_height(x,z), z)` 是否为空气，但该体素
   按定义必为实体，循环恒 continue。重写为"本列顶低于 8 邻域 ≥4 m 且向下连通空气 ≥60"。
4. 测试 helper 用 `ensure_chunk` 造"空世界"实际生成地形（新增 `fill_air_all_for_test`）；
   若干测试断言与几何预期错误（对角射线命中点、基岩层边界），逐一修正。

## D-10 · 地形参数修订与默认 Seed 更换（2026-09-13）

- **决定**：`mountain_mask_lo` 0.55→0.44、`mountain_amp` 58→78、`cave_threshold` 0.055→0.080；
  `DEFAULT_SEED` 20260912→12345。
- **理由**：原参数下多 seed 扫描（`examples/feature_scan`）显示山地掩码几乎不触发、
  洞穴通道从不穿透地表（所有 seed 均缺"山地"或"洞口"），属参数缺陷而非 seed 运气。
  修订后 42/7/12345 等多个 seed 八类特征齐备；选 12345 为固定验收预设因其余量最大
  （峰 115 m、总高差 112 m、洞口贯穿 -7 m）。不为使单一 seed 达标而继续特调参数
  （20260912 峰 79 m 差探测阈值 1 m），避免过拟合。

## D-11 · 验收运行时配置（沿用 V0.1，2026-09-13 复核）

- 世界 256×128×256（任务书下限），Chunk 16³（CPU 全常驻 ≈34 MiB 体素数据，
  1016 个非空 mesh 实体）；验收窗口 1280×720 + `PresentMode::Fifo`（VSync，帧率上限=刷新率，
  中位 FPS 门槛按显示器 ≥60 Hz 满足）；无阴影贴图（烘焙面着色，见 A13 性能余量）；
  GIF 480×270 每 4 s 一帧替代视频编码（无 ffmpeg 依赖）。
- greedy meshing 不启用：naive 面剔除在验收场景下性能余量充足（见报告 A13）。

## D-12 · 验收脚本形态（2026-09-13）

- **决定**：`scripts/acceptance.sh`（Git Bash）作为单一入口；`build_checks.json`
  由脚本写入、应用内 A01 判定读取。
- **理由**：开发环境为 Windows + Git Bash；脚本串起 fmt/clippy/依赖审计/测试/构建/运行

## D-13 · 渲染全黑根因与光照模型修订（2026-09-13）

- **根因（本轮最重要发现）**：`DistanceFog` 配置 `directional_light_color` 带 alpha 且
  `directional_light_exponent = 0.0`，触发 Bevy 0.19 PBR 雾散射分支
  `pow(max(dot(view,light),0), exponent)` 在 dot≤0 时的 WGSL 未定义行为
  `pow(0,0)`（NVIDIA/Vulkan 上为 NaN）。NaN 经 `mix(输入色, NaN, α)` 传播——
  即使雾 α=0，`NaN×0` 仍为 NaN，所有 PBR 片元被污染为黑。天空（clear 色不经过
  片元着色器）与 Gizmo/UI（独立管线）不受影响——这解释了四轮验收中
  "地形全黑剪影 + 天空正常"的稳定形态。修复：`directional_light_color: Color::NONE`
  （官方文档指定的禁用方式），shader 直接跳过散射分支。
- **光照模型修订**：V0.1 依赖"方向光 14000 lux（无阴影）+ 烘焙面朝向着色"。
  实测两个缺陷：背光面（N·L=0）只剩默认环境光 80 nits（≈直射的 0.6%）渲染成死黑；
  无阴影方向光把阳光"泄漏"进洞穴内部。修订为 **unlit 材质 + 烘焙顶点色明暗
  （FaceDir 系数 0.55..1.0）**，移除方向光——任意视角下调色板均保持可读
  （任务书 4.4"可读的基础光照"），洞穴内部可用性同时改善。
- **启示**：本例在四轮验收中均被"自动判定通过"（A04 仅检查截图非空与大小），
  直到本轮实现侧直接读取截图才暴露。截图类证据的"非空"检查不足以代表视觉可读性。

## D-14 · A08 相机入实体根因（2026-09-13）

- **根因一**：`collision_clamped_dist` 的 1.5 m 距离硬下限覆盖碰撞余量。山谷路点
  焦点被钳到 z=8.0（世界边界保护线）恰与 51 m 谷壁平面重合，DDA 在 t=0 命中，
  旧代码 `limit=(t-0.5).max(1.5)` 把眼位钉在墙体内，朝墙每帧计一次事件
  （628 s 巡航累计 854 次）。修复：允许实际距离收缩到 0（眼位退到焦点空气格），
  求解层下限同步放开；距离下限只保留在意图值 `target_dist`（脚本 ≥1.5 / 用户 ≥6）。
- **根因二**：A08 采样系统运行于相机求解之前，读到"上帧距离 + 本帧位姿"的瞬态
  错位。修复：`acceptance_control` 改为 `after(CameraSolve)`，采样即本帧真实眼位。
- 新增 `collision_clamped_dist` 单测 3 项（贴墙 t=0、margin 收缩、无命中）。

## D-15 · A06 跳变断言帧率无关化（2026-09-13）

- 旧断言用眼位速度阈值（150 m/s），但脚本平滑运动的切向速度随帧率缩放：
  240 fps 下 smoothstep 过渡峰值即超阈值（run4 误报 57 次）。改为帧间位移阈值
  （4 m/帧）：脚本平滑运动峰值 ~1 m/帧，真跳变/状态错乱为数十米级瞬移，
  阈值两侧各留一个数量级余量，且与帧率无关。

## D-18 · R1 返修：验收入口加固与相机焦点纠正（2026-09-13）

- **验收入口**（scripts/acceptance.sh）：运行前断言工作区干净并记录完整提交
  SHA（`commit.txt`）；证据目录必须全新（已存在非空目录立即失败，应用侧对
  screenshots/gif_frames 已有 PNG 再做第二道防线）；应用运行包裹总超时
  watchdog（卡死自动终止、留下 `watchdog.txt` 并以非零码退出）；结束后自动
  扫描运行日志中的 panic/ERROR/FATAL 与持续重复错误；机器信息拆分为
  `machine.txt`（OS/工具链）与 `machine.json`（GPU/驱动/图形后端/窗口模式/
  完整命令行/run_id/git SHA）。
- **相机焦点纠正**：焦点（轨道中心）此前只受边界钳制，普通键鼠控制横穿山体
  时会钻入实体体素（验收靠 `path_min_focus_y` 贴地保护规避，属验收专用补丁）。
  修复：`CameraRig::resolve_focus_out_of_solid` 在相机求解层对焦点所在列做
  实体检查，落在实体内时沿 +y 抬升到最近空气格顶面 + 0.3 m（贴地滑行；
  洞穴空气格不触发）。眼位碰撞钳制（DDA 收缩）不变，以纠正后的焦点为起点。
- **验收路径**：时间线新增低空普通控制路径（横穿山体 / 贴行悬崖 / 贴行世界
  边界，全部禁用 `path_min_focus_y` 保护），脚本焦点真实穿入地形，焦点纠错
  被有效演练；A06 覆盖判定要求"脚本焦点实体信号帧数 > 0"证明路径有效性，
  A08 增加"焦点入实体事件 = 0"硬门槛（眼位与振荡门槛同为 0，无容忍额度）。
- **A10 双帧率阶段**：低空段同时以每帧 20 ms 主动节流渲染帧，与正常帧率
  巡航窗构成两个显著不同的渲染帧率阶段，两阶段均断言 20±2% TPS 且实测
  FPS 均值分离 ≥1.15×（否则判定前提不成立）。
- **A03 逐体素比较**：新增"单 Chunk 生成 vs 全邻域生成"的逐位一致探针
  （3 seed × 3³ 世界全部 27 个边界 Chunk），与既有跨界列定义检查共同判定。
- **A04 证据归属**：8 张机位截图须通过保存记录比对、mtime 不早于本次运行、
  PNG 可解码、尺寸等于窗口、亮度统计排除全黑/全白/纯色五重检查；
  run_id（UNIX 秒-pid）写入 machine.json/report.json 贯穿证据链。
- **A07 队列清空时限**：每波脏事件"从 0 变正"到归 0 的时长 ≤5 s，
  且运行中至少观察到 3 波真实脏事件（TintOn/TintOff/编辑测试）。
- **A12 资源生命周期**：Mesh 资产/材质/Chunk Mesh 实体的创建与删除计数
  插桩（`MeshResourceStats`），1 Hz 时间序列进 metrics.csv 与
  resource_timeline.csv；守恒断言：创建-删除 = 在册数/资产总数。
- **world.rs 无效断言**：删除 `|| true` 恒真断言，改为与 `generate_chunk`
  纯函数直接输出的逐体素对照（覆盖边界行与内部抽样点）。
