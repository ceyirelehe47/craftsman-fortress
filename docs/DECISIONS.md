# 决策记录（Agent 自主决定项）

任务书第 9 节授权范围内的全部自主决策及理由。编号延续 V0.1 的 D-01..D-06（见 git 历史），
本轮 V0.2 从 D-07 起记。

## D-07 · Bevy 补丁版本与工具链（2026-09-13）

- **决定**：`bevy = "=0.19.1"`（精确锁死），`Cargo.lock` 一并提交；工具链 rustc **1.98.1**。
- **理由**：任务书冻结 0.19 系列。0.19.1 是当前最新补丁版。Bevy 0.19.1 的 MSRV 为 1.95.0、
  edition 2024，仓库原 1.86.0 工具链无法编译；选择 1.98.1（当前 stable，2026-09-01 发布），
  在 `rust-toolchain.toml` 锁定以保证可复现。0.19 系列内的后续补丁升级将作为独立依赖变更处理。

## D-08 · 升级策略：迁移而非重写（2026-09-13）

- **决定**：保留 V0.1 的模块划分与全部实现，按编译器/迁移指南逐点迁移到 0.19 API。
- **理由**：任务书 4.1 要求"保留可用实现，不无依据重写"。实际迁移共触碰 7 类 API
  （Trigger→On、EventWriter→MessageWriter、FontSize::Px、WindowResolution::new(u32)、
  gizmos.cube、shadow_maps_enabled、Assets::insert 返回值）+ 系统排序改为 SystemSet，
  均为局部改动，验证了原架构与 Bevy 解耦良好。

## D-09 · 升级中发现并修复的 V0.1 缺陷（2026-09-13）

升级使 V0.1 测试首次真正编译运行，暴露以下被掩盖的缺陷，全部修复：

1. **渲染顶点色格式**：`ATTRIBUTE_COLOR` 写入 `[f32;3]` 在 0.19 直接 panic（Float32x4 要求）。
   V0.1 无任何证据包留存与此吻合——渲染路径从未跑通。改为 RGBA(alpha=1.0)。
2. **`World::set_voxel` 返回值 bug**：文档承诺返回旧值，实现返回新值。已修。
3. **洞口探测恒失效**：探测检查 `voxel(x, column_height(x,z), z)` 是否为空气，但该体素
   按定义必为实体，循环恒 continue。重写为"本列顶低于 8 邻域 ≥4 m 且向下连通空气 ≥60"。
4. 测试 helper 用 `ensure_chunk` 造"空世界"实际生成地形（新增 `fill_air_all_for_test`）；
   若干测试断言与几何预期错误（对角射线命中点、基岩层边界），逐一修正。

## D-10 · 地形参数修订与默认 Seed 更换（2026-09-13）

- **决定**：`mountain_mask_lo` 0.55→0.44、`mountain_amp` 58→78、`cave_threshold` 0.055→0.080；
  `DEFAULT_SEED` 20260912→12345。
- **理由**：原参数下多 seed 扫描（`examples/feature_scan`）显示山地掩码几乎不触发、
  洞穴通道从不穿透地表（所有 seed 均缺"山地"或"洞口"），属参数缺陷而非 seed 运气。
  修订后 42/7/12345 等多个 seed 八类特征齐备；选 12345 为固定验收预设因其余量最大
  （峰 115 m、总高差 112 m、洞口贯穿 -7 m）。不为使单一 seed 达标而继续特调参数
  （20260912 峰 79 m 差探测阈值 1 m），避免过拟合。

## D-11 · 验收运行时配置（沿用 V0.1，2026-09-13 复核）

- 世界 256×128×256（任务书下限），Chunk 16³（CPU 全常驻 ≈34 MiB 体素数据，
  1016 个非空 mesh 实体）；验收窗口 1280×720 + `PresentMode::Fifo`（VSync，帧率上限=刷新率，
  中位 FPS 门槛按显示器 ≥60 Hz 满足）；无阴影贴图（烘焙面着色，见 A13 性能余量）；
  GIF 480×270 每 4 s 一帧替代视频编码（无 ffmpeg 依赖）。
- greedy meshing 不启用：naive 面剔除在验收场景下性能余量充足（见报告 A13）。

## D-12 · 验收脚本形态（2026-09-13）

- **决定**：`scripts/acceptance.sh`（Git Bash）作为单一入口；`build_checks.json`
  由脚本写入、应用内 A01 判定读取。
- **理由**：开发环境为 Windows + Git Bash；脚本串起 fmt/clippy/依赖审计/测试/构建/运行
  五段，任何一段失败立即非零退出，满足"任何被跳过、超时或无法运行的硬性检查均按失败处理"。
